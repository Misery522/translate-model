# 后续功能设计草案：身份、文字伙伴与语音

更新日期：2026-10-09。**本文件是实施前草案，不表示用户已批准新增能力，也不新增
公共 API、权限或存储。** 当前优先级仍是文字版真机稳定；安装和发布边界不变。

状态与验收入口：[项目动态进度](PROJECT_STATUS.md)、[Redmi 记录](REDMI_ACCEPTANCE.md)。

## 1. 已有协议与不能直接复用的地方

- Android 桥只有九项文字操作：健康、身份查询、配对、注销、创建/删除工作会话、
  翻译、查询任务、取消任务；配置只绑定指定私人 HTTPS 源，不是任意 HTTP 代理。
- 翻译模式为自动、文字翻译、代码注解、特殊内容注解，没有伙伴聊天或录音模式。
  原文最多 4000 字符；原生请求 32 KiB、响应 512 KiB，不能往文本字段塞音频。
- 当前 Bearer 只在 Java 内存，后台/销毁清身份与内容。配对码 5 分钟有效、一次使用；
  后端身份空闲 30 分钟、最长 24 小时，重启后失效。没有 refresh、可信设备注册
  或长期撤销协议，保存当前 Bearer 本身不能提供可靠的长期免配对。
- 文本任务异步创建和轮询；清空、取消、换地址和身份变化使用代次丢弃迟到结果。
  本地取消不等于 Ollama 同时停算；网络失败或进程被杀后仍需后端 TTL 兜底。
- 当前只申请 INTERNET，不保存翻译历史，不注册 Service Worker，不提供通用
  Shell/文件/网络工具；未来功能不得借此绕过权限和认证设计。

## 2. 身份与后台恢复

**默认建议：先做短时内存恢复，不做长期存储；此建议尚未批准。**

- 备选一：保持现状，每次后台重新配对，改动最少但不方便。
- 备选二（建议）：仅同一进程内允许最多 5 分钟后台身份恢复，不延长后端有效期。
  后台立即清原文/译文、作废请求代次，并有界取消/删除工作会话；不保留旧结果、
  不后台保活或自动刷新身份。返回先验证身份，再建立新的工作会话。
- 备选三：长期可信设备；需要单独设计设备注册、撤销、短期凭据与原生密钥保护，
  以及电脑重启行为。不是简单把现有 Bearer 写入 Preferences。

备选二必须显式改变当前后台注销行为：只能保留原生内存身份，不能保留工作任务。
5 分钟、进程销毁、退出、注销、换地址或后端 401 任一条件触发清身份；同地址保存
仍撤销旧代次。取消未确认时不得自动重投旧请求，并显示服务端清理尚未确认。

**成功条件：**真机后台返回不要求频繁配对，同时不会恢复旧内容；所有失效条件、
迟到回包、断线清理和资源上限有回归。若选择长期可信设备，先审查独立协议和隐私，
再决定是否实施，不自动启用备选三。

## 3. 会话式翻译与独立伙伴模式

**默认建议：先完善对话式翻译与 App 内宠物反馈；自由伙伴聊天单独选择。**

- 翻译与聊天使用明确模式，不把聊天指令塞进已有翻译文本并希望模型自行改变任务。
  翻译继续保持格式/术语保护；聊天若获批准，使用独立受限工作流和清晰结果类型。
- 宠物先反馈等待、理解、翻译、停止、离线、失败和配对状态，不增加悬浮窗、
  剪贴板监听或后台麦克风。使用原创或许可可核验的素材。
- 默认仅当前会话内存历史，建议最多 20 轮并有字符/上下文上限；清空、退出、
  地址或身份变化时删除。不要把模型上下文称作永久记忆或默默写入磁盘。
- 继续使用现有本机模型，不新增模型执行命令、任意工具调用或浏览网页能力。
  新任务通过独立接口设计审核后接入，不改写现有翻译结果语义。

**成功条件：**用户能分辨“翻译”与“聊天”；模式切换不串请求、历史或结果，清空
与取消仍正确；聊天不能改变翻译规则。语义质量需真实模型测试，不以 UI 动画替代。

## 4. 按住说话与后续连续口译

**默认建议：中英、按住说话、电脑端本地识别和播报；不默认使用云语音服务。**

- 先评估本地 ASR/TTS 候选的质量、许可、大小、CPU/GPU 占用和模型来源，再单独
  确认依赖/模型安装。系统语音服务可能联网，不能未经核验称其完全离线。
- 首版建议一次最多 30 秒、松开结束；录音前明确申请麦克风并显示状态，后台、
  停止或清空立即停止采集。不后台监听，不启用连续会话，也不一次申请未来权限。
- 识别 → 文本确认/修正 → 翻译 → 用户主动播报。默认不保存录音、转写和译文；
  临时数据只在有界任务中使用，结束、取消或超时清理，不进入公开日志和仓库。
- 音频需要独立的受限上传/识别/播报设计，限定格式、大小、时长、认证、限流和
  取消；原生桥也需要独立审查，不能增加“任意文件/URL上传”来绕过文本约束。
- 录音、识别、翻译和播放共用请求代次；迟到转写/译文/音频不得恢复清空内容。
  播放可打断，断线不自动重录或重投；文本客户端继续保留可用回退。

**成功条件：**固定中英短句真机对照，数字、否定、术语不能被无提示漏掉；录音
权限拒绝、短音频、弱网、取消、清空、后台和播报打断均有回归。质量和耗时明确
记录设备与候选，不先承诺实时性能。单段稳定后才设计双向断句、字幕、回声处理
和连续口译；不能把按住说话完成写成实时口译已交付。

## 5. 实施前需要用户选择

| 事项 | 建议默认 | 需要明确的选择 |
| --- | --- | --- |
| 后台身份 | 同进程最多 5 分钟，只存内存 | 保持现状 / 短时恢复 / 单独设计长期可信设备 |
| 文字产品 | 对话式翻译与宠物反馈 | 是否同时增加独立自由伙伴聊天 |
| 会话记录 | 仅当前会话内存，清空即删 | 是否需要跨重启历史；若需要另做存储隐私设计 |
| 宠物呈现 | App 内状态反馈 | 是否以后申请系统悬浮窗；首版不申请 |
| 语音范围 | 首版中英、按住说话 | 初始语言、30 秒建议上限和是否自动播报 |
| 语音处理位置 | 电脑本地 ASR/TTS | 电脑处理 / 手机处理；云服务不是默认项 |

未作选择时只能继续审查和准备，不据“推荐”直接实施新存储、权限或公共接口。
每一阶段都应先确定行为与接口、更新威胁模型、增加真实验收，再在隔离分支实现；
不影响现有桌面/PWA，不自动合并或发布。手机离线模型、华为/iPhone、OCR 和系统
悬浮宠物仍是独立项目，不因上述草案而被算作已交付。
