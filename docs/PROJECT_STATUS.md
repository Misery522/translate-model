  失败语义，不改生产执行方式，不跳过、重试或延长执行时限。
  验证基线 `da1ddb9` 的
  [push CI](https://github.com/Misery522/translate-model/actions/runs/37825252347) 和
  [PR CI](https://github.com/Misery522/translate-model/actions/runs/37825260310)

  这不能直接归为 Linux 的 10 秒探针故障；旧基线成功不抵消本次失败。
  已为 CI 测试入口和 pytest 子进程启用无缓冲输出与固定启动/超时/退出标记；
  整套仍为单次 60 秒，正常退出码透传，超时和启动失败保持非零，不输出异常正文。
- **验证依据：**2026-10-09 本机完整 Python 522 项通过（30.10 秒），隔离源码包
  同样 522 项通过（28.17 秒）；新增入口语义回归 12 项，实际 PowerShell 多行
  入口以这些用例试跑通过。远程基线与最终提交分别记录，不混称。20 项真实模型

- **下一步：**每次提交核对同一 SHA 的 push 和 PR CI；最新结果保留在
  [PR #27](https://github.com/Misery522/translate-model/pull/27)，不把本文历史基线
  当作最新门禁。继续源码审查，不自动重跑或创建监控；如果再次超时，按即时进度

  不读取命令、环境、内存或私有路径，预算耗尽不代表资源已回收。

## 接下来按什么顺序做

1. **先处理文档和 CI：**修正失效 Capacitor 说明，诊断 CI 间歇超时，记录最终提交
   与两类 CI 结果。完成条件为原因或剩余不确定性写清、最新门禁通过。
2. **准备但不安装：**登记设备版本、检查 APK 与私人服务、阅读配对步骤。完成条件
   为资料齐全，仍等待手机安装授权。
3. **授权后真机验收：**安装、配对、实际翻译与生命周期/网络验收；先修缺陷再加功能。
4. **并行整合桌面和源码：**保持独立审计/发布门禁，先在隔离整合分支修复真实冲突，
   再按依赖顺序审查 PR；不自动合并，也不覆盖活动桌面工作树。
5. **文字稳定后扩展：**按第 8 项顺序提交各功能设计，不把规划内容标为已完成。

## 更新规则与操作边界

- 每项固定记录 **状态／本次结果／验证依据／剩余问题／下一步**；状态使用
  未开始、进行中、待确认、待验收、已完成，并写明完成的是哪一层。
- 每轮只更新有效结论和必要证据；旧运行保留为历史引用，不重复堆积日志，也不
  将未运行的检查或未来设备反馈填成通过。
- 源码标签、内部试用、真机验收、GitHub Release 和正式发布分别记录；不根据
  标签存在推导已公开发布。
- 暂不安装手机、不自动合并 PR、不正式签名、不公开发布 APK；系统安装、环境
  修改、模型处理和其他高风险操作需要明确确认。
- 保持 API 回环监听、私人 Serve、Funnel 关闭；不直接暴露 Ollama 或 Gradio。
- 不删除模型、不覆盖旧 C++ 模板、不随意更换现有环境；现有试用服务保持可用。
- 原文、译文、配对码、令牌、私人词库和真实私人域名不进入公开文档或仓库。
- 当前不新增公共业务接口；语音、持久身份和手机离线模型另行设计。
